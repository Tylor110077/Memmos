# 学习知识图谱助手后端任务清单

## 1. 文档目标

本文档基于 [backend_design.md](/Users/tylor/Code/GoAIPj/backend_design.md) 输出后端实施任务清单，用于研发排期、迭代拆分和 MVP 范围控制。

标记说明：

- `MVP`：第一版必须完成，否则主流程不闭环。
- `Post-MVP`：可以在主流程打通后补充，不影响第一版最小可用。

## 2. MVP 完成标准

MVP 至少需要满足：

1. 可以创建、查看、重命名、删除分组。
2. 可以上传文件和提交网页链接。
3. 资源有清晰状态，失败可见且支持重试。
4. 资源处理完成后可查询资源级知识图谱。
5. 分组下可生成并查询框架图谱。
6. 点击节点可查询节点详情。
7. 用户可触发扩展节点。
8. 用户可围绕当前节点发起问答。

## 3. 任务拆分原则

1. 先打通“分组 -> 上传 -> 异步处理 -> 图谱查询”的主链路。
2. 再补“框架图谱 -> 节点详情 -> 扩展节点 -> 问答”。
3. 最后补可观测、性能优化和工程完善。

说明：

1. `BE-040` 手动触发框架图谱接口可以晚一点，只要资源完成后能自动生成。
2. `BE-053` 流式回答不是绝对阻塞项，非流式完整回答也能算 MVP。
3. `BE-064`、`BE-065` 属于建议纳入 MVP 的质量项，如果时间极紧，可先保留冒烟测试和主链路集成测试。

## 7. 交付建议

为了便于协作，可以将每个任务在项目管理工具中补充以下字段：

- 负责人
- 预计工时
- 前置依赖
- 风险点
- 验收人
- 测试方式

这样这份清单就可以直接转成 Sprint backlog，而不需要再做一次大的重新拆分。
