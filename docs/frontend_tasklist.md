# 学习知识图谱助手前端任务清单

## 1. 文档目标

本文档基于以下文档输出前端实施任务清单，并确保能够与后端任务清单并行推进：

- [front_requirement.md](/Users/tylor/Code/GoAIPj/docs/front_requirement.md)
- [frontend_api.md](/Users/tylor/Code/GoAIPj/docs/frontend_api.md)
- [backend_tasklist.md](/Users/tylor/Code/GoAIPj/docs/backend_tasklist.md)

本文档的目标不是只列页面名称，而是给出可执行、可排期、可并行开发的前端任务集合。

标记说明：

- `MVP`：第一版必须完成。
- `Post-MVP`：可以在 MVP 之后补充。

并行说明：

- `可独立并行`：前端可不依赖后端落地，直接基于需求和 mock 开发。
- `契约并行`：依赖接口文档和字段约定，可先 mock，后联调。
- `联调依赖`：需要后端完成对应接口后再联调验证。

## 2. 前端 MVP 完成标准

MVP 至少需要满足：

1. 可以浏览分组列表，并完成创建、重命名、删除。
2. 可以进入分组详情页，查看资源列表和资源处理状态。
3. 可以上传文件和提交网页链接。
4. 可以查看分组级框架图谱。
5. 可以进入资源图谱页，完成图谱浏览、缩放、拖动和层级过滤。
6. 可以点击节点查看详情。
7. 可以触发扩展节点。
8. 可以围绕当前节点发起问答。
9. 可以通过 SSE 感知资源状态和图谱更新。

## 3. 与后端并行开发策略

### 3.1 并行原则

1. 先冻结接口契约，再并行开发。
2. 前端在 `BE-013/018/034/039/042/046/052/054` 完成前，使用 mock 数据和 MSW 先推进页面与交互。
3. 图谱、侧栏、弹窗、表单、状态 UI 不等待后端即可完成。
4. 真正需要后端的只放在联调与验收阶段。

### 3.2 前端建议依赖物

前端并行开发时建议提前准备：

1. `frontend_api.md` 作为接口契约。
2. `mock` 数据文件，覆盖分组、资源、图谱、节点详情、会话、事件。
3. `MSW` 或本地 mock server。
4. 统一 `TypeScript` 类型定义。

## 8. 推荐协作方式

为了真正做到和后端并行，建议按以下协作方式推进：

1. 先冻结 [frontend_api.md](/Users/tylor/Code/GoAIPj/docs/frontend_api.md)。
2. 前端先完成 `mock + 页面 + 交互 + hooks`。
3. 后端按任务清单逐步交付接口。
4. 前端按模块逐步把 mock 切成真实 API。
5. SSE 和流式对话集中安排一次联调窗口，不要零散穿插。

这样前后端不会互相等待，也能把联调风险压到最后一小段，而不是贯穿整个开发周期。
