学习知识图谱助手前端设计语言与界面风格规范
1. 文档目标

本规范用于定义“学习知识图谱助手”第一版产品的前端设计语言、视觉风格、信息层次、页面布局、交互规则和关键组件表现形式，使设计和实现过程具备以下特征：

风格统一

功能优先

复杂内容可读

图谱交互稳定

AI 能够根据本规范生成较高一致性的界面

本规范面向：

UI 设计师

前端工程师

AI 设计生成工具

产品原型编写者

2. 产品界面设计总原则

本产品不是娱乐化产品，也不是重营销导向产品，而是一个以“知识理解、结构浏览、学习交互”为核心的工具型系统。因此整体界面应遵循以下原则：

2.1 整体气质

整体应呈现为：

理性

安静

清晰

可信

有结构感

适度现代

不炫技

不应呈现为：

过于花哨

高饱和冲击

强营销感

过度拟物

过度游戏化

视觉元素过多导致注意力分散

2.2 设计关键词

建议前端设计语言围绕以下关键词建立：

Structured

Calm

Precise

Lightweight

Knowledge-first

Explainable

Expandable

中文可理解为：

结构化

冷静

准确

轻量

以知识为核心

可解释

可扩展

2.3 体验核心

界面的首要目标不是“惊艳”，而是让用户在面对复杂资料和图谱时仍能稳定理解：

当前在哪个分组

当前看的是哪个资源

当前图谱属于哪个层级

当前选中的是哪个节点

当前对话基于什么上下文

哪些内容来自原始资料，哪些来自系统扩展

3. 整体视觉风格定义
3.1 风格方向

整体采用：

现代化、轻量化、知识工作台风格

可参考的抽象风格方向：

Notion 的秩序感

Linear 的克制感

Figma / Excalidraw 的工作区理性布局

专业数据产品的面板化组织方式

但不要直接模仿任何具体产品。

3.2 视觉基调

视觉基调应以浅色模式为主，支持后续扩展深色模式，但第一版建议先把浅色模式打磨清楚。

浅色模式应具备：

大面积低噪声背景

轻层级面板

中性灰为主的文本与边框

低饱和主色点缀

图谱中通过颜色区分层级与类型，但不能刺眼

3.3 造型语言

界面造型建议统一为：

中小圆角

轻边框

轻阴影

扁平化为主

局部悬浮感

建议：

卡片圆角：12px

小按钮圆角：10px

输入框圆角：10px

面板圆角：14px

弹窗圆角：16px

不要使用：

极大圆角导致玩具感

很厚重的阴影

强玻璃拟态

过强渐变背景

4. 配色系统规范
4.1 配色原则

本产品配色必须服务于以下目标：

让文本阅读舒适

让图谱层级清晰

让交互状态明确

让系统扩展节点与原始节点可以区分

让用户长时间使用不疲劳

整体配色应以 中性色 + 单一主色 + 少量功能色 为核心。

4.2 基础中性色

建议使用偏冷的中性色体系，提升理性和科技感，但不能太蓝导致界面发冷。

次级背景：#FFFFFF

悬浮层背景：#FFFFFF

边框色

一级边框：#E3E8EF

二级边框：#D7DEE7

强调边框：#C8D2DF

文本色

一级文本：#1F2937

二级文本：#4B5563

三级文本：#6B7280

反白文本：#FFFFFF

4.3 主品牌色

建议主色采用：

低饱和知识蓝 / 静态蓝

推荐主色：

Primary 500：#4F7CFF

图谱中的焦点节点

为什么不用更鲜艳的蓝：

太鲜艳会破坏长时间学习场景的稳定感

图谱里颜色本来就很多，主色要克制

图谱不能完全沿用普通 UI 配色，需要额外定义专用节点色，但必须保持低饱和、可区分、可长时间观看。

5. 字体与排版系统
5.1 字体建议

中文建议使用：

优先：Inter + 思源黑体 / Noto Sans SC

备选：PingFang SC / Microsoft YaHei / system-ui

如果只使用系统字体，也可以接受，但需要保持干净现代。

5.2 字重规范

建议只使用以下几个字重：

400：正文

500：强调正文 / 标签

600：标题 / 面板标题 / 按钮

700：少量大标题

不要频繁混用过多字重。

5.3 字号层级

建议统一字号体系：

页面主标题：24px / 600

页面区块标题：18px / 600

面板标题：16px / 600

正文：14px / 400

辅助文字：13px / 400

标签 / 状态文字：12px / 500

图谱节点文字：12px 或 13px / 500

5.4 行高建议

标题行高：1.3

正文行高：1.6

辅助说明：1.5

节点详情正文：1.7

原因是该产品阅读量较大，正文需要更舒展。

6. 间距与布局网格系统
6.1 基础间距单位

建议采用 4px 基础栅格系统。

常用间距：

4

6.2 页面留白原则

整体留白要足够，不能面板挤压。

建议：

页面外边距：24px

面板内边距：16px 或 20px

模块之间间距：16px / 24px

表单项之间：12px / 16px

6.3 信息密度原则

这是一个知识型工具，不应做成过于宽松的营销页面，也不能过于拥挤。

建议密度：

比企业官网更紧凑

比典型后台系统更舒展

比 IDE 更友好

7. 全局布局设计
7.1 整体框架

第一版建议采用 三段式工作台布局，根据页面不同略有变化。

常规结构：

左侧全局导航区

中央主内容区

右侧上下文区 / 详情区 / 对话区

这是最适合该产品的结构，因为产品天然包含：

分组导航

图谱主画布

节点详情与对话上下文

7.2 左侧导航区

左侧导航应固定存在，承担全局切换功能。

建议宽度

240px

包含内容

产品 Logo / 名称

分组入口

当前分组列表

创建分组按钮

最近访问

资源入口或二级导航

风格要求

浅色背景略深于主内容区

当前选中项有明显高亮底色

图标简洁线性风格

层级关系清楚

建议背景：

#F8FAFC 或 #F7F9FC

7.3 中央主内容区

中央区域承担主要内容展示，具体根据页面切换：

分组列表

分组详情

图谱画布

资源列表

框架图谱

这是视觉重心所在。

风格要求

保持最大可用空间

尽量减少不必要边框

让图谱区占最大面积

顶部保留轻量工具栏

7.4 右侧上下文区

右侧区域用于承载：

节点详情

节点来源

示例

关系说明

侧边栏对话

建议宽度

360px 到 420px

风格要求

独立面板

与主画布有清晰分隔

可折叠

内部区块清晰分层

8. 核心页面设计规范
8.1 分组列表页
页面目标

让用户快速理解自己有哪些项目空间，并进入对应分组。

页面布局

建议采用：

顶部标题区

搜索 / 筛选区

分组卡片网格或列表区

分组卡片样式

每个分组卡片包含：

分组名称

简短说明或资源数量

最近更新时间

进入按钮或点击整体进入

更多操作按钮

卡片视觉

白底

轻边框

轻阴影

hover 时略提升

卡片尺寸

建议中等尺寸，不宜过高。

8.2 分组详情页
页面目标

让用户在一个项目空间中管理资源并进入整体图谱。

布局建议

从上到下：

顶部区域

分组名称

分组描述（可选）

上传资源按钮

上传网页按钮

查看框架图谱按钮

中间区域

建议分为两部分：

资源列表区

分组级框架图谱预览区或入口区

资源列表

每条资源显示：

资源名称

类型标签

上传时间

状态

操作按钮

状态标签颜色要统一：

已完成：绿色

处理中：橙色或蓝色

失败：红色

等待中：灰色

8.3 资源图谱页

这是最关键页面，必须重点规范。

页面目标

让用户围绕某个资源的知识图谱进行浏览、理解、扩展与问答。

推荐布局

采用三栏布局：

左侧：资源与图谱控制栏

宽度建议 260px 左右，包含：

返回分组

当前资源名称

资源类型

图谱层级过滤

节点类型图例

图谱缩放控制

重新布局按钮

仅看主干 / 显示扩展节点开关

中间：图谱主画布

占据页面最大面积，是核心区域。

右侧：节点详情与对话侧栏

显示当前节点详情和聊天区域。

资源图谱页的视觉重点

必须保证：

图谱画布最突出

控制区域不喧宾夺主

右侧详情面板信息可读

页面视觉焦点随着“选中节点”而移动

8.4 框架图谱页
页面目标

用于查看某个分组下的整体高层结构。

设计要求

相比资源图谱页，框架图谱页应更“概览型”。

应有特点

节点数量相对更少

层级更清楚

颜色更统一

更偏导航，不偏细节解释

页面建议

中间大画布展示整体框架

右侧显示当前高层节点简要说明

不强调对话入口，或弱化对话入口

9. 图谱画布专项设计规范
9.1 画布背景

图谱画布背景不要纯白，建议用极浅灰蓝色，方便区分节点与白色面板。

推荐：

#F7FAFD 或 #F8FBFE

可叠加非常轻的点阵或网格感，但必须非常弱，几乎不可察觉，只用于提升空间感。

不要使用：

明显网格线

深色背景

花纹背景

9.2 节点形态

节点建议使用：

圆角矩形节点

而不是纯圆点。因为该产品节点通常承载概念名，圆角矩形更适合文字表达和点击操作。

节点尺寸

节点宽度自适应，但应设置：

最小宽度：80px

最大宽度：180px

高度：36px 到 44px

节点内容

节点内部只展示：

简洁节点标题

不要在节点上堆过多信息。

节点阴影

仅使用极轻阴影，hover 时略增强。

9.3 边与箭头

第一版建议：

线条柔和

不强制全部箭头可视

更强调连接关系而非流程导向

如果使用箭头，箭头应很小且简洁。

边标签第一版可选，不必默认大面积显示，否则会很乱。
建议在点击节点或 hover 关系时再显示关系说明。

9.4 动画原则

图谱动画必须克制。

建议使用：

初始进入时轻微淡入与位置展开

拖拽时平滑移动

选中时缓慢高亮

布局变更时平滑过渡

不要使用：

弹跳过强

大幅旋转

频繁脉冲

复杂粒子特效

因为会破坏学习场景专注感。

9.5 图谱层级控制组件

层级控制建议使用：

双端滑块
或

分段选择器

例如：

1-2

2-3

3-4

全部

界面上必须明确说明：
“显示层级范围”

不要只放一个抽象 slider 而没有解释。

9.6 节点图例

图谱页中需要有一个轻量图例，帮助用户理解颜色和类型。

应包含：

主干节点

系统扩展节点

当前选中节点

关系线

图例位置可以放在左侧控制栏下部。

10. 节点详情面板设计规范
10.1 面板结构

右侧详情面板建议分为几个清晰模块：

节点标题区

节点元信息区

节点解释区

节点意义区

示例区

相邻关系区

操作区

对话区

10.2 节点标题区

展示：

节点名称

节点类型标签

来源标签

是否为系统扩展节点

来源标签建议使用低饱和胶囊标签：

原始抽取

归纳生成

系统扩展

10.3 解释区与意义区

两者应视觉分开。

解释区

回答“它是什么”

意义区

回答“它在当前主题里为什么重要”

这两个区块不要混在一起，否则不利于学习理解。

10.4 示例区

示例区建议采用轻背景块包裹。

如果示例是系统生成的，应加一个弱标签：

系统示例

如果示例来自资料，可标：

资料示例

10.5 相邻关系区

建议列表式展示：

与哪个节点相关

关系是什么

点击相邻关系项时，应能联动图谱聚焦对应节点。

10.6 节点操作区

建议包含：

生成相关补充知识点

聚焦到该节点

在对话中提问

操作按钮层级要清楚：

主操作：生成补充知识点

次操作：聚焦、查看关系等

11. 侧边栏对话设计规范
11.1 对话区域定位

侧边栏对话不是通用聊天机器人，而是：

节点上下文学习助手

所以界面要明确当前上下文。

11.2 对话头部

必须显示上下文说明，例如：

当前节点：xxx

当前分组背景：已启用

框架图谱：未纳入当前上下文

这样可以显著降低用户对回答范围的误解。

11.3 对话消息样式

建议采用简洁气泡，但不要过于聊天社交化。

用户消息

靠右

主色浅底

文本清晰

系统消息

靠左

白底或浅灰底

结构化排版更强

系统回答允许包含：

小标题

短段落

例子块

引导性说明

不要把回答做成过厚的纯文本墙。

11.4 输入框设计

底部输入框应固定。

建议支持：

单行输入，自动扩展到多行

占位提示明确指向当前节点

发送按钮清晰

占位文案类似：
“围绕当前节点提问，系统会结合分组背景帮助解释”

状态

节点类型

12.4 卡片

卡片用于：

资源

白底

13. 状态设计规范
13.1 Hover

所有可点击元素 hover 必须有反馈，包括：

颜色轻微变化

边框变化

阴影轻微增强

鼠标样式变化

13.2 Active

点击中状态要有压感，但非常轻。

13.3 Selected

选中状态必须强于 hover，且在图谱节点、导航项、资源项中保持一致逻辑。

13.4 Disabled

禁用状态必须明显：

降低透明度

去除阴影

不可点击

13.5 Loading

loading 要尽量稳定克制：

骨架屏

轻量 spinner

文案明确

不要让加载动画过度活跃。

14. 空状态、异常状态与边界状态
14.1 空分组状态

当没有任何分组时：

展示简洁插画或图标

提示创建第一个项目空间

主按钮突出

14.2 空资源状态

当分组内没有资源时：

提示上传文件或网页

两个入口要清楚区分

14.3 图谱为空状态

当资源解析成功但暂时未生成图谱或图谱内容不足时：

不要出现空白页面

应显示说明：

资源正在生成图谱

或当前内容不足以形成清晰图谱

14.4 节点未选中状态

右侧面板应有默认说明：

请选择图谱中的一个节点查看详情或发起对话

14.5 处理失败状态

失败状态需要：

红色轻提示

错误说明

重试入口

18. 供 AI 稳定生成界面的明确指令

下面这部分可以直接作为 AI 生成设计稿或前端页面时的风格指令。

18.1 全局风格指令

设计一个桌面端知识工作台产品界面，整体风格要求现代、安静、理性、轻量、结构清晰。
使用浅色主题，大面积低噪声背景，白色卡片和浅灰蓝工作区。
主色使用低饱和知识蓝，避免高饱和霓虹色。
整体界面强调信息层次、阅读舒适性和长时间使用的稳定感。
不要使用营销化设计、夸张渐变、强玻璃拟态、重阴影、过度动画。

18.2 页面布局指令

采用桌面端三栏工作台布局：

左侧固定导航栏

中间主内容区或图谱画布

右侧详情与对话面板

中间画布区域必须最大化，右侧用于节点详情和对话，左侧用于导航和图谱控制。
布局要清楚区分全局导航、当前内容和上下文信息。

18.3 图谱样式指令

图谱使用浅背景画布和圆角矩形节点。
主干节点按层级使用同一蓝色系的深浅变化。
系统扩展节点使用更浅、更柔和的紫灰色，明显区别于主干节点。
当前选中节点必须有统一高亮描边。
边线柔和细腻，不要过粗，不要复杂箭头。
动画要克制、平滑，适合知识浏览场景。

18.4 详情面板指令

右侧详情面板分为多个清晰区块：

节点标题

来源标签

概念解释

主题意义

示例

相邻关系

节点操作

对话区域

信息分层必须明确，不能全部堆成一块文本。

18.5 组件风格指令

按钮、输入框、标签、卡片统一采用：

中小圆角

轻边框

轻阴影

扁平现代风格

按钮层级清楚，主按钮使用低饱和蓝色，次按钮使用白底边框样式。
标签使用低饱和胶囊样式，不要使用过强颜色块。

19. 最终视觉结论

这套前端设计不应该是“炫酷的图谱产品”，而应该是：

一个让用户在复杂资料中保持冷静、看清结构、稳定学习的知识工作台。

视觉上应做到：

有专业感

有结构感

有学习氛围

有轻量现代感

不打扰理解过程

交互上应做到：

图谱是主角

节点学习链路清晰

扩展节点有明确区分

对话始终围绕当前节点上下文
